# Automations.Admin.pts

## 2026-11-02 - External automation writer actions
Trial patch for the external-driver design (2026-11-02). Authored in the scratch clone only; not applied to C:\dev\FeedingFrenzy.
- `ToListFeedingFrenzyAutomationDraftsDue(AutomationKey, Offset, PageSize)`: read-only administrator action for `automation-review/get-drafts-due`.
- `ToAttachFeedingFrenzyAutomationDraft(AutomationKey, DefinitionVersion, LeadID, EpisodeID, Occurrence, Email, DraftJson)`: guarded administrator write for `automation-review/attach-draft`. The identity fields are typed; `DraftJson` is the `AutomationResearchDraft` object parsed with `new JsonObject(DraftJson)` (precedent: TwitterXApi) and nested as `Request.Draft` (nested-object precedent: WikiHelp). It creates a pending email for human review and never sends.
- `ToWriteFeedingFrenzyAutomationDraftsSkill`: prompt action for `Prompts/WriteAutomationDrafts.prompt.md`, which carries the in-process writer's rules and the list, research, attach and paging loop.
- All three use `FeedingFrenzyJsonWsService#Current`, like every action in this skill. The installation is chosen by the session's Current binding; local validation must run in a session whose Current points at `http://feedingfrenzy.local`.
- Validation: parsed with ProtoScript.Parsers `Files.ParseFileContents` (a broken control snippet was rejected). Not compiled into a running Buffaly project, the lazy index was not regenerated, and the actions were not called against a server.

## 2026-11-02 - Make the writer actions callable by the embedded agent
Problem: the first live Buffaly run on local IF (embedded session of the `feeding-frenzy-if-accounting-administrator` agent) answered that the session had no tool to attach drafts or holds.

Cause, from source: `BuffalyAgent.RegisterTools` (Buffaly.Agent.Host/BuffalyAgent.cs) passes the session's active roots to `ToolRegistrar.RegisterAllSemanticPrograms`. For this agent the roots are `RootActionPrototypeName` = `FeedingFrenzyJsonWsSkillAction`, the PromptContext skill `IntelligenceFactoryAccountingSkill` and its ActionRoot. The registrar calls `ProtoScriptRuntime.GetDescendantsForRoots`, which uses `Prototype.GetDescendants()`. That returns direct children only (`DescendantsCollection`; `GetAllDescendants()` is the recursive form). So:
- `ToListFeedingFrenzyAutomationDraftsDue : FeedingFrenzyJsonWsAdminAction` was a grandchild of the root and never registered.
- `ToAttachFeedingFrenzyAutomationDraft : FeedingFrenzyJsonWsAdminGuardedWriteAction` was a great-grandchild.
- `ToWriteFeedingFrenzyAutomationDraftsSkill : PromptAction` was outside the root.
- The prompt named `ToSearchTheWebWithAnLLM`, which is defined in Core/PromptActionTools.pts and is not in the administrator include graph.

Change:
- Re-based `ToListFeedingFrenzyAutomationDraftsDue` and `ToAttachFeedingFrenzyAutomationDraft` onto `FeedingFrenzyJsonWsSkillAction`. Parameters, Execute bodies and routes are unchanged. The attach description now starts with "Guarded administrator write.", because the GuardedWrite base was only a classification; no runtime code checks it.
- Administrator-only scope still comes from the include graph: only Skills/FeedingFrenzyJsonWs/Administrator.pts includes this file, the same pattern as `Users_GetUser` and `Tasks_GetTask`. The server still requires `HasSuperAdminAccess` for both routes.
- Added `ToResearchFeedingFrenzyAutomationProspect(question)`: a read-only thin wrapper over `_opsAgent.AskModelViaRuntime(question, "", "", "", "", "[]", true)`, the same call that core OpsAgent `ToSearchTheWebWithAnLLM` has used since buffaly-development commit 6ec4a43a6 (2026-10-30). It runs native live web search on the session's runtime selection, which must be openai/codex_backend; otherwise the host returns an explicit failure (`ValidateRuntimeWebSearchSelection`), with no API-key, other-model or no-search fallback. `_opsAgent` is the existing `extern IAgentRuntimeHost` from Imports.pts, which Administrator.pts includes. The first draft of this action called `LLMs.ExecuteWebSearch(question)` (copied from FeedingFrenzy Core/PromptActionTools.pts); that method no longer exists in Buffaly.Agent.Tools.Llm, and live run 2 below shows the call returned null with no error.
- `ToWriteFeedingFrenzyAutomationDraftsSkill` is now `: PromptAction, FeedingFrenzyJsonWsSkillAction` (precedent: OpsAgent `HelpAgentPromptAction : PromptAction, HelpAgentActionRoot`).
- Prompts/WriteAutomationDrafts.prompt.md now names `ToResearchFeedingFrenzyAutomationProspect` instead of `ToSearchTheWebWithAnLLM`.
- Precedent for changing the direct parent: Skills/IntelligenceFactoryAccounting/Review.pts.md, which re-parented `ToReviewIfAccountingTransaction` for the same nonrecursive registrar.

Not changed: AdminFoundation.pts. Other actions that are still grandchildren of the root (for example `ToInsertFeedingFrenzyLead` and `Tasks_InsertTask`) remain uncallable by this registrar; that is pre-existing and reported in the external-driver design ledger. Skills/FeedingFrenzyJsonWs/index.pts.lazy.json was not regenerated; no FeedingFrenzy agent entry file includes Skills/index.pts.

Validation: FeedingFrenzy.Agent.Tools.Tests, built with `-p:BuildProjectReferences=false` because the sibling Buffaly.Chat.Contracts project currently fails to resolve BasicUtilities: 73 of 75 passed, including the new direct-parent and sales-exclusion assertions in `DedicatedProject_LoadedGraphExcludesBroadAgentCapabilities`. The 2 failures (`VerasolLocalPilotHasADedicatedAuthorityAndCredentialWithCommunicationsDisabled` and `EmbeddedChat_UsesSameOriginServiceRoundTripWithoutIframe`) read files this change does not touch. Live load and the Buffaly end-to-end run on local IF are recorded below.
