# Annotations.pts Change History

## Purpose
- Declares the annotation functions that FeedingFrenzyAgent ProtoScript roots use on prototype definitions. `SemanticProgram.InfinitivePhrase` and `SemanticEntity` register semantic entries through `SemanticDatabase` (`InsertSemanticProgram` and `InsertSemanticEntity`). `SemanticContext` declares a ContextPrompt phrase and writes nothing.
- Included as the second line of Administrator.pts, MyOutreach.pts, SalesRepresentative.pts, Sms.pts, TTGCommerce.pts and VerasolHelp.pts, directly after `Imports.pts`, which supplies the `SemanticDatabase` reference and import this file depends on.

## Add SemanticContext Phrase Declaration (2026-11-16)
- Changed: added `function SemanticContext(Prototype prototype, string phrase) : void` with an empty body and a two-line comment. Its text equals the declaration in Buffaly core `content/projects/OpsAgent/Annotations.pts` at buffaly-development 6153e366d9a8087dc247f915b4504d586940137d. `InfinitivePhrase` and `SemanticEntity` are unchanged.
- Why: `ContextPrompts/index.pts` now declares context phrases with `[SemanticContext("...")]` annotations, and the ProtoScript compiler rejects an annotation whose function is undeclared ("Unknown function: SemanticContext"). Any root that compiles context definitions needs this declaration.
- Design decision and invariant: the function is syntax only and must stay empty. Compilation performs no semantic write. The context registration owner reads the literal from source, then performs and verifies the upsert, so the phrase has one representation and one write path.
- Dependencies: Buffaly core N1 or later reads the annotation. The declaration adds no prototype and changes no existing annotation. No other FeedingFrenzy source declares `SemanticContext`.
- Verification run: the isolated FeedingFrenzy compile harness (54 checks passing, none failing; log SHA256 6426F8AE98ECC3D1E909D23E5F58F1B5358A3386EEF6509C5928FFD4EF08A4F8) compiled this file with an `Imports.pts`-equivalent prelude together with the migrated `ContextPrompts/index.pts`, using the exact N1 core binaries. Startup diagnostics were only the accepted service-root skip, and the declaration and comment equal core's. Removing only this declaration made the compile fail with "Unknown function: SemanticContext".
- Verification run: `VerasolHelpProfileTests` in FeedingFrenzy.Agent.Tools.Tests (Debug, `BuffalySdkDirectory` set to the core Buffaly.Agent.Host Release output) ran 3 tests. The role-selection test and the VerasolHelp.pts include-graph test, which scans this file, passed. `HelpProfiles_AssembleSharedResearchWithoutQuestionMappings` failed with `TargetParameterCountException` before reaching any FeedingFrenzy content, because core 0acf8932216f0267c000ddcfb800723518051263 added a third optional parameter to `PromptAssembly.AssembleRequiredContextPromptText` while the test reflects with two arguments. That failure is independent of this change and is not fixed here.
- Limitations: the six roots were not compiled end to end in a running FeedingFrenzy host. No staging, installed or Matt-local copy was changed.
